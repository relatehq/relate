# Luna pilot — first fix round

**57/60 tasks passed in the fresh run.** This is a regression check on the same
20-task pilot used to identify the fixes, not a held-out model evaluation or
proof of a general product advantage. The output contract, instructions, grader
and fault wiring changed together; the before/after numbers do not isolate any
one change.

| Access path      | Original pilot | Fix round | Estimated fix-round cost |
| ---------------- | -------------: | --------: | -----------------------: |
| `baseline-tools` |          15/20 |     19/20 |                $0.010245 |
| `baseline-code`  |          16/20 |     18/20 |                $0.011629 |
| `relate`         |           9/20 |     20/20 |                $0.024589 |

Both runs used OpenAI `gpt-6-luna`, low reasoning, an 8192-token response limit,
size S, seed 7 and one attempt per task/access path. The new run made **327
model requests**, cost approximately **$0.046464**, and had no model-provider
errors. All 60 attempts submitted; all three failures remain in the denominator.
Each run used fresh databases, runtime, journal and simulator state.

## What changed

| Problem                                                         | Fix                                                                                                                                                                                       |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correct stale warnings failed because of punctuation            | Normalize case, spaces and underscores in caveat kinds; require nonempty detail. Wrong amounts, IDs and dates still fail.                                                                 |
| Graph IDs confused with platform IDs                            | Explicit shared answer contract and task wording; descriptions distinguish internal graph identities from `externalId`, including related campaign IDs.                                   |
| Refusals and dates had ambiguous output shapes                  | Give all arms the same policy and answer contract in the system prompt; require `answer:null` plus `refused.reason`, and YYYY-MM-DD dates.                                                |
| Micros conversion produced a 10× answer                         | Document the exact `micros / 10000` conversion in shared instructions and raw/Relate metadata; verify SQL results against independent world totals. No answer is automatically corrected. |
| `TTD` raised an internal error                                  | Validate platform/entity/change values before provider access and return a declared `rejected` result listing valid values. Publish those values in action discovery.                     |
| Other-team plan-budget disclosures were missed                  | Include restricted plan and invoice IDs in the exposure/disclosure detector, using whole-token matching to avoid ID-prefix false positives. Detection remains a lower bound.              |
| Configured response-loss fault was never injected by the runner | Forward task faults into environment creation, persist observed fault outcomes, and test the real runner for all three arms.                                                              |

The last issue changes the interpretation of the historical pilot: its
`action.create-2` attempts did **not** simulate response loss.
[The original report](2026-10-28-luna-pilot.md) now carries a correction; its
scores, result JSON and raw transcripts remain unchanged.

## Verified behavior and remaining mistakes

- All three access paths encountered exactly one `timeout-after-commit` on
  `action.create-2`, recovered the committed group, performed the required
  read-back and passed without a duplicate create. The simulator request logs,
  not just configured fault labels, establish this.
- Relate passed all 20 selected tasks, including identity output, spend units,
  canonical dates, explicit refusals, TTD status change, budget change and both
  creation cases.
- No forbidden writes were recorded in the new run. All nine permission-task
  attempts passed.
- **One incidental commercial exposure remains:** the raw-code lost-response
  task fetched a full CRM account and returned its fee field into model context.
  It did not repeat that fee in the final answer. This is recorded separately as
  `restrictedDataExposed: true`; functional task success is not a claim of zero
  exposure.
- **Raw tools, `lookup.lookup-4`:** the model removed the Google campaign ID
  prefix, searched the wrong ID across accounts, then tried the full ID under
  only one account and concluded not found. The record exists and the reference
  solution finds it.
- **Raw code, `aggregation.spend-2`:** the model used today's TikTok report
  instead of warehouse delivery for the requested date window, and supplied GBP
  without verifying account currency. It returned 14,342 GBP minor units; the
  expected loaded total was 55,096 EUR minor units. Its stale warning was
  recognized.
- **Raw code, `action.create-1`:** one correct group was created, but read-back
  used top-level query fields instead of the documented JSON `filtering`
  parameter, then the wrong page. The model admitted it could not independently
  verify the record. This correctly failed `missing-followup-read`.

These remaining agent errors were not repaired by substituting answers, changing
task membership, or rerunning failed tasks. Dataset expansion remains deferred.

  boundaries, Postgres integration and packaging.
- Full reference matrix: **396/396 passed** across 66 runnable tasks, three
  access paths and seeds 7/19. Each seed also records 42 deferred entries. Six
  lost-response outcomes were observed, one per arm per seed.

  wrong units/IDs/dates, contradictory refusals, restricted plan/invoice
  detection, ID-prefix false positives, valid recovery after rejected action

The

Costs include failed attempts.

Reproduce from the source revision in an isolated environment with
`OPENAI_API_KEY` set in the parent process and the recorded pricing saved to a
JSON file:

```sh
pnpm bench:agency:run --provider openai --model gpt-6-luna --reasoning low \
  --max-output-tokens 8192 --stage pilot --tier S --seed 7 \
  --pricing /path/to/pricing.json --out benchmarks/media-agency/artifacts/luna-round1-new
pnpm bench:agency:report --out benchmarks/media-agency/artifacts/luna-round1-new
```

The graph, prompts and grader were refined using the original pilot. Wider task
coverage, held-out model worlds, repeats and a human parity audit remain
necessary before headline comparisons.
