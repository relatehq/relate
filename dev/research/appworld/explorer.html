Nano, with the current Relate SDK

AppWorld research · Results, execution architecture and individual agent trajectories

Can a small model use Relate through discovery alone? This rerun uses the merged SDK contracts and errors, plus one shared completion instruction in the system prompt.

No per-turn completion reminders. No new graph, acquisition, wrapper, or REPL behavior. The primary rerun uses nano on four tasks, across three conditions and three repeats.
These recorded runs predate the SDK-only environment. Their SDK agents could also call original APIs. The current runner exposes only relate and completeTask; it has not been benchmarked again yet.

One-time environment instruction

The same instruction is appended to each condition’s system prompt. It is not part of the SDK and is not repeated after each cell.

Printing a result does not complete the task. When finished, call the completion API described above with your final answer. For numeric questions, submit only the numeric value, without explanatory text, currency symbols, or units. For questions asking for a name or title, submit only that name or title, without explanatory text. Follow any answer-format requirements stated in the task.

Findings from the rerun

Reading the measurements

Official success is the original AppWorld evaluator’s verdict. Completion is a separate event: a submitted answer can still be wrong. Token counts sum every model call, including repeated input history; cached input is included in input tokens. Cost is an estimate using the recorded model prices, not an invoice.

SDK wall time includes host acquisition and graph initialization. All source calls include authentication and acquisition; agent source calls exclude those setup phases and host completion polling. A snapshot fetch is not the same as an SDK query. Each episode runs in a fresh world.

This is an exploratory training-task experiment, not a benchmark leaderboard score. Two tasks are familiar, one addition is a same-family payment variant, and one introduces a song-selection family. Language, pre-acquisition and authored graph semantics differ across arms. The SDK and completion prompt changed together, so historical differences do not identify either change’s causal effect.

The agent writes TypeScript. Node.js executes it. Python owns the benchmark, calls the model, and evaluates the result.

Language ≠ runtime. TypeScript is JavaScript with extra syntax for types. We transpile each cell into JavaScript, then hand it to Node’s REPL. This setup does not type-check the agent’s code.

What survives between turns?

One Node child process and one REPL context live for the whole SDK episode. Variables, helper functions, and the injected SDK consumer persist. A new episode starts fresh. 

// Cell 1 — type annotation is removed before execution
var count: number = 3;
console.log(count); // 3

// Cell 2 — same REPL context
count += 2;
console.log(count); // 5

// Cell 3 — top-level await works
console.log(await relate.describe());

These are illustrative cells, not a live terminal. The trace viewer contains actual recorded executions. Only printed output is returned; a bare expression’s value is discarded by our worker callback.

Repeating a const or let declaration may cause “already declared” errors. Runtime errors are returned as observations, allowing another turn.

Two paths out of a TypeScript cell

Agent cell
  ├─ await relate.objects.Person.query(...)
  │    → actual Relate SDK / runtime
  │    → task-local acquired snapshot
  │    → compact SDK result
  │
  └─ await apis.venmo.some_operation({...})
       → JavaScript Proxy / pending Promise
       → JSON line to Python host
       → original AppWorld API
       → api-result JSON line
       → Promise resolves inside the same cell

relate is the real actor-bound SDK consumer. apis is an asynchronous bridge to the original simulator. The graph is populated through public APIs before agent execution; it is not a live per-query Spotify or Venmo connector.

Python remains the host because AppWorld is Python-based. Relate code is executed in Node, not translated into Python.

The graph we authored

Playlist ← Membership → Song
   └──────── songs() ────────┘

Person ← Transaction.sender
Person ← Transaction.receiver

Membership records represent a song’s inclusion in a playlist. A song can belong to several playlists. Explicit Playlist.traverse.songs() lets the caller cross this association without manually querying Membership.

Person identity uses an exact-email join during acquisition. These mappings and descriptions were authored by us, not discovered from scratch by the model.

Limits and measurement boundaries

Boundary Actual implementation
Execution One cell at a time; asynchronous API responses can resolve during that cell. A 60-second cell timeout kills the Node child.
Output console methods capture text; up to 14,000 characters are shown to the model per turn. Full recorded output is separately available.
TypeScript Syntax transpilation and syntax diagnostics only. No semantic type-checking, editor completions, or auto-imports.
Permissions Node permission flags constrain readable code/dependencies and deny ungranted capabilities. Host globals are masked; only PATH and NODE_NO_WARNINGS enter the child environment. A VM context alone is not a security boundary.
Source mutations Non-GET/HEAD source requests close the acquired snapshot before resolving the proxy promise. This implementation has no snapshot refresh API.
Scoring After the episode, Python flushes direct API changes to AppWorld’s evaluator inputs, saves, and invokes the original evaluator. Printing the right number is not official task completion.
Tokens and timing Input tokens include repeated history; cached tokens are a subset. Output tokens include reasoning. Episode wall time includes setup; per-turn model/execution timings are recorded separately.
