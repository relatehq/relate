# Luna pilot — hardened world v2

**The benchmark is no longer saturated.** On the v1 catalogue, the fix-round
pilot passed 57/60. On world v2, the same model and settings pass 50–77% per
arm, and Relate no longer leads on accuracy.

All runs: OpenAI `gpt-6-luna`, low reasoning, 8192 output tokens, tier S, one
attempt per task and access path, the 22-task v2 pilot, fresh environments per
attempt, isolated containers. 198 attempts in total, 1,794 model requests, about
$0.53 estimated, with no provider errors. Every failure stays in the
denominator.

**How to read this.** Pilot A identified four harness defects (below), which
were fixed before the rerun. The seed 7 rerun is therefore regression evidence
on the pilot used to find them. Seed 19 uses the same task designs with
different targets and values: it is not a held-out task design. One attempt per
cell gives wide intervals; pass^k, more seeds and tier M remain outstanding.

## What changed from v1

See the README's "Coverage (world v2)" for the full list. In short:

- **Tasks name things the way people do.** Campaigns are found by name across
  opaque IDs. Clients are reached through CRM merge survivors and dashed or
  `act_` account IDs.
- **Policy needs data.** A team's ownership lives in CRM. Other cases are a 25%
  budget move, a shared Google budget, an ended flight, and requests that are
  only partly permitted.
- **The deferred work runs.** FX by channel converts per delivery day; pacing
  and diagnose-then-act use per-account load cutoffs.
- **Actions fail realistically.** Bulk brand-safety pauses cross platforms, with
  a 429, a 500 and a lost response, and some ads must be skipped.

## Harness defects found by pilot A (fixed in `14b8ca0`)

| Defect                                                                                                                               | Fix                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Status values were undocumented and simulators accepted anything; models used TikTok's real `ENABLE`/`DISABLE` and were marked wrong | Document `ACTIVE`/`PAUSED` for every platform; simulators reject other values (TikTok code 40001, 400)                    |
| Google search on a dashed or unknown customer ID silently returned no rows                                                           | Return `INVALID_CUSTOMER_ID`, as the real API rejects it                                                                  |
| Contract said both "refuse when policy forbids" and "answer null for uncompletable tasks"; correct no-write declines failed          | Handbook-rule actions (budget limit, shared budget, ended flight) accept either; team/fee authority still needs `refused` |
| Handbook "malformed names are ambiguous" was read as excluding a client's own campaigns from ownership lists                         | State that ownership comes from the account link, never from the name                                                     |

**A systematic Relate finding.** Priya's team-scoped read policy hides other
teams' clients completely. The agent cannot tell "forbidden" from "does not
exist", so it reports "not found". It fails every data-dependent refusal and, on
mixed requests, sometimes abandons the permitted half. This is an integration
and product signal: the graph should state that records were withheld by policy
rather than return an empty result.

**Relate DX papercuts seen in transcripts:** int64 computed filters reject
numbers (`gt: 0` must be `gt: '0'`); malformed `compute` SQL errors led the
model to give up on reconciliation and pauses; per-day FX needs up to 8
expressions per query because reference-dataset joins do not exist yet.

**Cost.** Relate used 2.1–3.3× the input tokens of raw code (4.4M vs 1.3M on
seed 19) and cost 2.4–3.0× more per run, with lower pass rates. The largest
single request was 358,177 input tokens (seed 19). The flat pricing file assumes
the short-context tier; the long-context threshold for this model was not
verified, so long requests may be underpriced.
